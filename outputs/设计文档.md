# 基于多种深度学习经典模型的视觉学习系统的设计与实现

## 摘要

本系统面向视觉学习任务，采用前后端分离架构，设计并实现了一个可交互、可训练、可对比的视觉学习平台。
前端使用 Vue 3 + Vite + Element Plus + ECharts 构建单页应用；后端基于 Python + Django REST Framework 提供
RESTful 接口，算法层使用 PyTorch 从零复现了 LeNet-5、AlexNet、VGG、GoogLeNet、ResNet、DenseNet、
MobileNetV2、SqueezeNet 等 10 种经典卷积神经网络。系统支持数据集管理、在线训练与实时进度监控、
单图识别、批量识别、多模型对比识别、混淆矩阵与分类别指标可视化、识别历史与统计分析。
系统还设计了独立的用户登录模块（新疆师范大学标识 + Token 鉴权 + 前端路由守卫），
除登录与健康检查外的全部接口均需登录后访问，识别记录会关联到具体操作人。
在自带演示数据集（6 类几何图形，1440 张 64×64 图片）上，ResNet-18 训练 12 轮即可达到 90.28% 的验证准确率，
且整套系统在纯 CPU 环境下即可完成全部流程。

## 一、课题背景与意义

图像识别是深度学习最成功的应用方向之一。从 1998 年 LeNet-5 用于手写数字识别，到 2012 年 AlexNet 在
ImageNet 上把 Top-5 错误率从 26% 降到 15%，再到 VGG、GoogLeNet、ResNet、DenseNet 与 MobileNet 系列，
卷积神经网络在结构设计上不断演进：**更深、更宽、更高效**。

然而在教学与工程实践中，往往存在两个断层：

1. **算法与工程脱节**：教材讲的是网络结构，实际项目却是数据管道、任务调度、接口设计与可视化；
2. **经典模型难以横向对比**：不同论文的模型往往运行在不同数据集、不同训练配置下，缺少统一平台做同条件对比。

本课题希望用一个完整可运行的 Web 系统来同时解决这两个问题：既把 10 种经典网络放在同一个数据管道与
训练引擎下做同条件对比，又给出从数据上传、训练调度、模型管理到推理服务、统计分析的全链路工程实现。

## 三、系统总体设计

### 3.1 技术选型

| 层次 | 技术 | 选型理由 |
| --- | --- | --- |
| 前端框架 | Vue 3（组合式 API）+ Vite | 轻量、上手快、构建速度快，适合单页交互型系统 |

### 3.3 关键流程

**训练流程（时序）**

```
前端表单 ──POST /api/training-runs/──▶ 校验超参数 ──▶ 落库（status=pending）
        ◀── 返回任务对象 ──        └──▶ TrainingManager.start() 启动后台线程
后台线程：加载数据集 → 构建网络 → 训练循环（on_batch/on_epoch 回调回写进度）
        → 保存最优权重 .pt → 创建 TrainedModel 记录 → 自动激活（若无默认或精度更高）
前端：每 2 秒轮询 /progress/ 与 /log/ 刷新进度条、曲线与日志
```

**推理流程**

```
上传图片 ──▶ 校验大小/格式 ──▶ PIL 解码为 RGB
        ──▶ 定位模型（显式 id > 该结构默认模型 > 最新模型）
        ──▶ 预处理（Resize + ToTensor + Normalize）
        ──▶ 前向推理 → Softmax → Top-K
        ──▶ 写入 PredictionRecord（含图片、Top-K、耗时）
        ──▶ 返回结果给前端
```

**登录与鉴权流程**

```
访客访问任意受保护页面 ──▶ 前端路由守卫读取本地 Token
        无 Token ──▶ 跳转 /login?redirect=原地址
        有 Token ──▶ 放行，Axios 请求头自动附加 Authorization: Token <key>
提交账号密码 ──▶ POST /api/auth/login/ ──▶ Django authenticate()
        成功 ──▶ 签发/复用 Token，写入 last_login，返回用户信息
               ──▶ 前端 Pinia 保存用户，Token 写入 localStorage（记住我）或 sessionStorage
        失败 ──▶ 表单内联提示「用户名或密码错误」
任意接口返回 401 ──▶ 清除本地 Token ──▶ 跳回登录页（记录原地址）
修改密码 / 退出登录 ──▶ 删除该用户全部 Token ──▶ 所有会话立即失效
```

## 四、数据库设计

### 4.1 实体关系

```
User(Django 内置) 1 ──── 1 Token（认证令牌，修改密码/退出即删除）
User 1 ──── n PredictionRecord（记录是谁发起的识别）

Dataset 1 ──── n TrainingRun 1 ──── 1 TrainedModel 1 ──── n PredictionRecord
   │                  │                    │                     │
   └──── n TrainedModel┘                    └──── 记录推理所用模型 ─┘
```

用户体系直接复用 Django 的 `auth_user`；认证令牌使用 DRF 的 `authtoken_token` 表
（`user_id` 一对一 + `key` 唯一），因此无需自建密码表即可获得可靠的账号、密码散列与令牌撤销能力。

系统支持 SQLite 与 MySQL 两种数据库后端，二者共用同一套模型定义与迁移脚本，切换方式见下一节。

### 4.1.1 数据库后端切换（SQLite ⇄ MySQL）

| 关注点 | 说明 |
| --- | --- |
| 切换方式 | 设置环境变量 `IR_DB_ENGINE=mysql` 及 `IR_DB_NAME / IR_DB_USER / IR_DB_PASSWORD / IR_DB_HOST / IR_DB_PORT`，业务代码零改动 |
| 字符集 | MySQL 必须使用 `utf8mb4`（校名、类别名等中文数据），已在 `settings.py` 的 `OPTIONS` 中固定 |
| 驱动 | 优先 `mysqlclient`，未安装时自动回退到纯 Python 的 `pymysql`（项目虚拟环境已内置，无需编译） |
| 版本要求 | 模型中使用了 `JSONField`（训练曲线、评估指标），MySQL 需 5.7.8+，推荐 8.0+ |
| 迁移工具 | `scripts/mysql_setup.sql` 建库建号；`scripts/migrate_to_mysql.sh` 完成「导出 → 建表 → 导入 → 校验」 |
| 部署方式 | 推荐用 Docker 运行 MySQL：`docker-compose.yml` 定义 `mysql:8.0`（服务端 utf8mb4、数据卷持久化、healthcheck），`docker compose up -d` 即可；也支持本机 `brew install mysql` |
| 回退 | SQLite 文件 `backend/db.sqlite3` 不会被删除，去掉环境变量即可切回 |

实测环境：Docker Desktop 20.10.17 + MySQL 8.0.46 容器，`docker compose up -d` 后约 15 秒进入
`healthy`；迁移后 4 张业务表、用户表与令牌表均位于 MySQL 中，中文字段以 `CHAR_LENGTH=10 /
LENGTH=28` 正确存储（表排序规则 `utf8mb4_unicode_ci`），前端功能与 SQLite 模式完全一致。

## 五、算法设计

### 5.1 经典网络结构的实现要点

- **统一接口**：所有网络接受 `(num_classes, in_channels)` 参数，输出 logits；
  末端统一使用 `AdaptiveAvgPool2d` 适配任意输入尺寸，使同一结构既能训练 32×32 的小数据集，
  也能训练 224×224 的标准输入。
- **LeNet-5**：`Conv(6,5×5) → MaxPool → Conv(16,5×5) → MaxPool → FC120 → FC84 → FC`，
  保留原论文的层次与通道数，输入通道改为可配置以支持彩色图像。
- **AlexNet**：`11×11/stride4` 大卷积核 + 5 层卷积 + 两层 4096 全连接，保留 Dropout 与 ReLU。
- **VGG**：以 `3×3` 卷积堆叠为特征提取器（VGG-11 / VGG-16 两种配置），后接两层 4096 全连接。
- **GoogLeNet**：Inception 模块包含 `1×1`、`3×3`、`5×5` 卷积与 `3×3` 池化四路分支，
  在通道维拼接；训练阶段引入两个辅助分类器，损失按 `L = L_main + 0.3·(L_aux1 + L_aux2)` 加权。
- **ResNet**：BasicBlock（ResNet-18）与 Bottleneck（ResNet-50）两种残差块，
  Bottleneck 采用零初始化残差分支最后一层 BN 的权重，提升深层网络初期稳定性。
- **DenseNet**：DenseBlock 中每层输入为前面所有层输出的拼接，Transition 层用 `1×1` 卷积 + 平均池化减半。
- **MobileNetV2**：倒残差结构（先升维再深度可分离卷积再降维），线性瓶颈避免 ReLU 破坏低维特征。
- **SqueezeNet**：Fire 模块 = squeeze（1×1 降通道）+ expand（1×1 与 3×3 并行升通道）。

### 5.2 数据管道与数据增强

训练集增强流水线：

```
Resize → RandomResizedCrop(scale=0.7~1.0) → RandomHorizontalFlip
      → RandomRotation(±15°) → ColorJitter(亮度/对比度/饱和度 ±0.25)
      → ToTensor → Normalize(ImageNet 均值方差) → RandomErasing(p=0.15)
```

验证与推理仅使用确定性的 `Resize → ToTensor → Normalize`，保证评估可复现。

数据集划分支持两种情况：显式的 `train/`、`val/` 子目录直接使用；扁平的 `<类别>/` 目录按
**分层抽样**切分（每个类别按比例抽取验证样本，且至少保留 1 张），保证类别分布一致。

### 5.3 训练策略

- **优化器**：SGD（momentum 0.9 + Nesterov）/ Adam / AdamW 可选；
- **学习率策略**：Cosine 退火 / 阶梯衰减 / 固定，学习率随轮次变化并写入曲线；
- **梯度裁剪**：`clip_grad_norm_(5.0)`，抑制偶发梯度爆炸；
- **混合精度**：CUDA 环境自动启用 AMP，CPU / MPS 使用 FP32；
- **标签平滑**：可配置 `label_smoothing`，缓解过拟合与过度自信；
- **类别加权**：样本不均衡时按 `total / (C · count_i)` 加权交叉熵；
- **最优权重选择**：每个 epoch 结束后在验证集评估，保存验证准确率最高时的权重快照，
  训练结束加载该快照再做一次完整评估（混淆矩阵、分类别指标）。

### 5.4 评估指标

准确率 = 正确样本数 / 总样本数；对每个类别分别计算
`Precision = TP/(TP+FP)`、`Recall = TP/(TP+FN)`、`F1 = 2PR/(P+R)`，并取宏平均。
全部指标基于混淆矩阵用 NumPy 实现，不引入 scikit-learn 依赖。

## 六、关键实现技术

1. **后台异步训练**：`TrainingManager` 单例维护 `run_id → 线程/停止事件` 映射，训练在守护线程中执行；
   每 1.5 秒节流回写一次进度到数据库，避免高频写库；线程结束时统一 `connections.close_all()` 释放
   SQLite 连接。停止采用协作式中止（在当前 epoch 结束后停止并保存已有结果），保证权重与记录一致。
2. **权重缓存**：`ModelStore` 以模型 id + 更新时间戳作为缓存版本，最多缓存 8 个模型，
   LRU 淘汰；模型删除或重新训练后自动失效，避免重复读盘与重复构图。
3. **对比推理**：`predict_compare` 对每个模型独立 try/except，个别模型缺少权重或权重损坏时
   跳过并返回 `unavailable` 列表，不影响其它模型参与对比；预测结果以多数投票给出共识标签与一致率。
4. **前端进度轮询**：区分「列表刷新（低频）」与「当前任务进度（2 秒）」两个接口，
   `/progress/` 只返回运行态与曲线等小字段，避免长轮询传输大 JSON。
5. **单端口部署**：Django 在检测到 `frontend/dist` 存在时，用自定义视图托管静态资源并对未知路径
   回退 `index.html`，支持 Vue Router 的 history 模式，无需额外 Nginx 配置即可演示。
6. **登录态与权限控制**：
   - 后端通过 `DEFAULT_AUTHENTICATION_CLASSES` + `DEFAULT_PERMISSION_CLASSES` 统一开启
     `IsAuthenticated`，仅登录、登录页配置与健康检查接口显式声明 `AllowAny`，避免逐个接口遗漏鉴权；
   - 前端在 Axios 请求拦截器中自动注入 `Authorization: Token <key>`，在响应拦截器里统一处理 401：
     清理令牌并跳转登录页，同时把当前地址写入 `redirect` 参数，登录后回到原页面；
   - 「记住我」勾选时令牌写入 `localStorage`（持久），不勾选时写入 `sessionStorage`（关闭标签页即失效）；
   - 修改密码后由服务端删除该用户的全部令牌并签发新令牌返回给当前客户端，实现「改密即踢出其它设备」。
7. **两级角色权限（管理员 / 普通用户）**：
   - 角色直接复用 Django 用户表的 `is_staff` 字段，不额外建表：
     管理员（`is_staff=True`）、普通用户（`is_staff=False`）；
   - 后端在 `apps/recognition/permissions.py` 中定义两个权限类：
     `IsAdminOrReadOnly`（读操作放行、写操作要求管理员）与 `IsAdmin`（纯管理接口）；
     前者挂在数据集、训练任务、模型库、识别记录四个 ViewSet 上，后者挂在用户管理接口上。
     这样「查训练进度」这类读接口所有登录用户都能用，而「发起训练 / 删除模型」只有管理员可以，
     权限判断以后端为准，绕过前端界面直接调接口同样会被 403 拒绝；
   - 前端由路由 `meta.adminOnly` 标记管理类页面（模型训练、数据集、用户管理），
     路由守卫读取本地用户信息拦截越权访问，侧边栏按角色过滤菜单，删除类按钮用
     `v-if="auth.isAdmin"` 控制显隐，列表页对普通用户显示「当前为普通用户视图」的说明；
   - 用户管理接口对危险操作加了业务约束：不能删除/停用当前登录账号、不能取消自己的管理员身份、
     系统至少保留一个可用管理员、账号已有识别记录时建议停用而非删除。

### 7.2 模型对比实验

**实验设置**：演示数据集（6 类几何图形，720 张 64×64 原图，其中训练 576 / 验证 144），
输入尺寸与轮数按模型规模调整，优化器 SGD（momentum 0.9），Cosine 学习率退火，初始学习率 0.01，
批大小 32，数据增强开启，设备为 CPU（8 线程）。

| 网络 | 输入尺寸 | 轮数 | 验证准确率 | 宏平均 F1 | 参数量 | 训练耗时(CPU) |
| --- | --- | --- | --- | --- | --- | --- |
| LeNet-5 | 32×32 | 3 | 23.61% | 0.1510 | 0.062 M | 2.1 s |
| ResNet-18 | 64×64 | 12 | **90.28%** | 0.9006 | 11.18 M | 106.0 s |

> 说明：上表为在开发机（Apple Silicon，8 核 CPU，PyTorch 2.12）上真实跑出的结果，
> 可通过页面「模型训练」或命令行 `python manage.py train -a <结构> -d 演示数据集-几何图形` 复现。
> 其余结构的对照实验可在同一数据集上自行开跑；需要注意的是 **MobileNetV2 的深度可分离卷积
> 在 CPU 上受线程数影响极大**（实测批大小 32、64×64 输入时：1 线程约 1.3 s/batch，
> 8 线程约 13.8 s/batch），系统已内置「分组卷积占比高则自动降低线程数」的启发式策略
> （见 `ml/engine.py` 的 `choose_cpu_threads`），也支持用环境变量 `IR_TORCH_THREADS` 手动指定。

**结论**

1. **深度与结构设计比参数量更重要**：ResNet-18 仅 11.18M 参数，验证准确率达到 90.28%，
   而 LeNet-5（0.06M 参数）在同一数据集上明显欠拟合；但参数量最大的模型（如 VGG-16）也并非最优，
   说明残差连接、BatchNorm 等结构设计对优化难度的改善比单纯堆参数更关键。
2. **轻量模型在中小数据集上性价比高**：MobileNetV2、SqueezeNet 参数量小、推理快，
   在该数据集上的精度损失有限，适合算力受限场景。
3. **训练耗时与参数量并非线性关系**：耗时还取决于输入分辨率与卷积计算量（如 AlexNet 的
   大卷积核与 4096 维全连接层，在 CPU 上代价明显）。
4. **数据增强对小数据集至关重要**：演示数据集每类仅 120 张，开启随机裁剪、旋转、色彩抖动与
   随机擦除后，模型在验证集上的泛化能力显著优于不做增强的配置。

## 八、总结与展望

本系统完成了一个「算法 — 服务 — 界面」贯通的多模型视觉学习平台：算法层从零复现了 10 种经典卷积网络
并封装为统一的训练/推理引擎；服务层用 Django REST Framework 提供规范化接口并解决了后台训练调度、
模型版本管理、用户认证与记录归档问题；界面层用 Vue 3 实现了登录鉴权、训练监控、识别交互与多维可视化。系统在纯 CPU、
完全离线的环境下可完整跑通全部流程，具备良好的教学演示与二次开发价值。

后续可扩展方向：

1. **迁移学习**：接入 ImageNet 预训练权重，支持「冻结骨干 + 微调分类头」的迁移学习模式；
2. **目标检测与分割**：在现有分类能力之上扩展 YOLO / Mask R-CNN 等任务的接口与可视化；
3. **任务队列与多机训练**：以 Celery + Redis 替代线程模型，支持排队、并发与多 GPU 分布式训练；
4. **模型优化与部署**：引入剪枝、量化、ONNX/TensorRT 导出与边缘端部署；
5. **可解释性**：增加 Grad-CAM 热力图，直观展示模型关注区域；
6. **更细粒度的权限体系**：当前已实现登录鉴权与操作人记录，后续可细化为「管理员 / 教师 / 学生」的角色权限，
   并为每个用户隔离数据集与识别记录。
